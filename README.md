# v2 · 岛岛（3D，进行中）

把小红书的收藏专辑捏成一座岛：每个专辑是岛上的一个地方，走进去逛、翻开看、动手做。视觉方向：小红书红 + 黏土风（参考 REDesign 2025 年度报告），品牌字“岛岛”用造字工坊，其余文字用系统默认字体，向导是黏土版的“岛岛”。

```bash
npm run world        # 打开 http://localhost:4180
npm run world:check  # 桌面 + 手机完整走查截图 → test-results/world/（需先 npm run world）
```

## 演示路径（约 5 分钟）

1. **第一次打开**：岛岛打招呼 → 起称呼（输入，或点切换按钮换一个，比如“吃灰专辑抢救员”“专辑达人”）→「你好，XX · 点点兴趣，岛岛收藏~」选择授权上岛的专辑（开关，可以只授权一部分）→ 看着房子一栋栋捏出来。
2. **岛上**：左上“岛岛”，中间“XXX的岛岛”。点中间的岛岛会跳一下、换一句话（台词贴着专辑里的帖子）。没授权的专辑是一块“待上岛”的空地，点它可以补授权。
3. **博物馆 · 睡莲巡回展**：序厅 → 错过的展 → 还能去的展 → 即将开幕 → 出口花园，序厅迎宾是岛岛。
4. **日记本 · 想成为的我**：书桌上一本翻页书。封面 → 扉页 → 目录（点条目直接翻到那篇）→ 12 篇各一个跨页（左页：标题、原作者、拍立得、评论区便利贴、看原帖；右页：打动你的一句话、能马上做的小事（可打勾）、给收藏它时的自己写回信）→ 后记（完成进度）→ 结语（封存成一年后的时间胶囊）。桌上软木板的拍立得也能直接翻到对应那篇。
5. **分享 / 访客**：每个地方都能分享入场券或借阅卡；带 `?from=名字` 打开是访客视角（日记本只能看、不能替主人打勾）。

操作：桌面拖动 / 滚轮 / WASD / 方向键；手机拖动、点按，日记本竖屏一次看一页（点屏幕右侧往后翻、左侧往回翻，也可以左右滑）。
重新走一遍新用户引导：岛上左下角「换个称呼 · 重新授权」，或打开 `#/?new=1`。

## 线上地址与部署

- 线上：https://daodao-iota.vercel.app（Vercel 项目 `senyuan/daodao`，只发布 `world/` 目录，全站 noindex）
- 重新部署：在项目根目录运行 `npx vercel@50 deploy --prod`（本机 Node 18，需用 vercel@50；最新版要求 Node 20）
- `*.vercel.app` 在中国大陆网络下被 DNS 污染，打不开；要在国内直接访问，需要绑定自己的域名（CNAME 指向 `cname.vercel-dns.com`）
- GitHub 推送后自动部署：需要先在 GitHub 给 Vercel 应用开放这个仓库的权限，再运行 `npx vercel@50 git connect`

> 图片和文字来自小红书公开笔记，仅用于原型演示；每件展品、每一篇都保留原作者和原帖链接，线上页面不被搜索引擎收录。
> 造字工坊是商业字体，线上只嵌入了“岛”一个字；正式对外发布前需要确认网页嵌入授权。

# 拾间 SHIJIAN · 让收藏里的喜欢，重新发生

把小红书的收藏专辑，变成一场可以走进去的**私人小展**、一本可以翻开的**桌上画册**、一家可以逛的**审美小店**——自己重温，也发给朋友、发回社区。

这是一个可交互的产品原型（独立网页 Demo），用来验证产品逻辑和体验，没有接入小红书的真实数据。

## 运行

```bash
npm install          # 只用于运行测试（Playwright）；页面本身没有依赖
npm run dev          # 打开 http://localhost:4173
```

## 演示路径（约 5 分钟）

1. **首页**：看“同一个「字画」专辑，三个人做出了三种样子”，点进任意一个，以访客身份逛一逛。
2. **开始创造**：选专辑「字画」（或贴任意链接）→ 看识别结果，点掉一两件 → 看推荐的“私人小展”和推荐理由 → 在想法里点“想要深夜美术馆的感觉”，风格会自动换成「午夜展厅」→ 生成。
3. **逛自己的展**：滚轮或方向键横向行走，点作品放大细看、留言；走到出口有留言簿。
4. **编辑**：右上角「编辑」，把形式切到“桌上画册”再切到“审美小店”，同一份收藏会换一种形状；改标题、换封面、调顺序都会立即生效。
5. **分享**：「分享」→ 发给朋友（入场券式邀请卡 + 链接）/ 发到小红书（笔记预览 + 发布到社区）。
6. **访客视角**：点「在新窗口以访客身份打开」，在新窗口留言；回到原窗口，作者会收到“新留言”提示。
7. **我的作品**：再次打开作品时，会提示“专辑里多了 2 条新收藏”，可以放进作品，也可以保留当前版本。

## 已确定的产品方向

| 主题 | 结论 |
|---|---|
| 要解决的问题 | 收藏只承接了“当时的喜欢”，缺少一个让喜欢再次发生的场景；专辑也没法作为一个整体分享出去 |
| 首批用户 | 有兴趣积累、会建专辑分类收藏、却很少回看的人 |
| 核心价值 | 自己重温 + 邀请别人进入（朋友、社区）在首版同时成立 |
| 产品形态 | 一套“专辑 → 作品”的形式系列：小展、画册、小店，之后可扩展音乐会、系列课等 |
| 推荐原则 | 内容帮我们推荐，用户决定这次变成什么；推荐必须附理由，并用用户自己的内容做预览 |
| 用户负担 | 只需贴链接 / 选专辑；风格和“一句想法”都是选填；先给完整初稿，再允许修改 |
| 与原收藏的关系 | 每件内容保留原笔记、收藏时间；作品持续关联原专辑，专辑更新时提示同步 |

## 功能清单

- **创建工作台**：链接输入 / 从“我的专辑”选择 → 识别动画与内容标签 → 排除内容 → 形式推荐（理由 + 实时预览）→ 风格（9 种）→ 一句想法（读取对象、氛围、风格暗示）→ 生成过程
- **私人小展**：序厅、按形制分展厅（团扇册页 / 立轴 / 长卷）、聚光与展签、横向漫步、进度条、出口留言簿
- **桌上画册**：3D 翻页、封面 / 扉页 / 目录 / 批注页 / 作品页 / 后记 / 留言页 / 封底，键盘与触屏翻页
- **审美小店**：门面与推门动画、收藏自动做成明信片 / 冰箱贴 / 书签 / 帆布袋 / 徽章 / 小挂画 / 器物、拿起旋转看背面、纸袋、用一句话结账并出小票
- **细看**：放大镜、导览词、原笔记与馆藏来源、逐件留言
- **编辑**：形式、风格、标题候选、开场白重写、封面、顺序、增删内容、删除作品
- **分享**：邀请卡（入场券 / 画册 / 开业邀请）、可直接打开的邀请链接、小红书笔记预览、发布到社区
- **访客**：邀请封面、收藏、留言、转发、“我也做一个”
- **社区灵感 / 我的作品**：瀑布流筛选、喜欢；作品状态（已发布、留言数、专辑新收藏）、收藏的作品

## Demo 中的模拟部分

- **链接识别**：不会读取小红书。任意链接匹配到样例专辑，识别和生成由规则模拟（见 `src/lib/generate.js`，输入输出已按以后接入模型的方式组织）。
- **数据**：作品、留言、收藏保存在本机浏览器 localStorage；邀请链接把作品内容编码在网址里，所以别的浏览器也能打开，但留言只在本机可见。
- **内容**：图片来自大都会艺术博物馆开放获取（CC0）藏品；中文作品名为意译；导览词、“原笔记”标题和社区用户为虚构。

## 下一步待讨论

1. **链接解析的可行性**：小红书笔记 / 专辑能否在合规前提下读取图片与文字，失败时怎样降级。
2. **他人内容的版权与署名**：收藏的是别人的笔记，作品分享出去时如何展示原作者、是否需要授权。
3. **验证指标**：比如生成率、分享率、访客停留与留言、作品的二次打开率、访客“我也做一个”的转化。
4. **更多形式**：私人音乐会（音乐类专辑）、系列课（教程类专辑）的编排规则。
5. **作者与访客的连接**：留言是否通知作者，访客是否可以关注作者或收藏单件内容。
